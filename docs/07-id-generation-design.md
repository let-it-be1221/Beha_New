> Spec §5.1, §6, §9, §12. Design for all four ID types + sequence management + history.

## 1. The Four ID Types

|---|----------------------|-------------------|----------------------------|------------------------------------------------|
| 1 | Official ID          | `BH000001`        | Record Officer (auto-gen)  | All authorized users                            |

## 2. Official ID (spec §5.1)

### Format

```
BH + zero-padded sequential number (default 6 digits)
```

Examples: `BH000001`, `BH000002`, ..., `BH999999`, `BH1000000` (auto-widens).

### Rules

- Prefix `BH` is **configurable** via `OFFICIAL_ID_PREFIX` env var.
- Padding length is **configurable** via `OFFICIAL_ID_PAD_LENGTH` (default 6).
- Sequence is **monotonic** — once issued, never reused, never resequenced.
- Stored on `users.official_id` (UNIQUE).
- Generated automatically inside the applicant onboarding workflow at step `record_verification`.
- Immutable for the user's lifetime — no manual editing.

### Sequence Storage

```text
table: id_sequences
  sequence_key = 'official_id'
  next_value   = N+1   (atomically advanced)
  prefix       = 'BH'
  padding      = 6
```

### Implementation

```php
// app/Services/ID/OfficialIdGenerator.php
class OfficialIdGenerator
{
    public function __construct(
        private IdSequenceService $sequences,
        private IdHistoryRecorder $history,
    ) {}

    public function next(): string
    {
        return DB::transaction(function () {
            // SELECT ... FOR UPDATE — lock the row
            $seq = $this->sequences->lockNext('official_id');
            $value = $seq->prefix . str_pad($seq->next_value, $seq->padding, '0', STR_PAD_LEFT);
            $this->sequences->advance('official_id');
            $this->history->record('official_id', $value, ...);
            return $value;
        });
    }
}
```

### Failure Modes

| Scenario | Handling |
|----------|----------|
| Concurrent requests | `SELECT FOR UPDATE` on the sequence row serializes |
| Transaction rollback | Sequence NOT rolled back — gap is acceptable (audit integrity > zero-gap) |
| Manual insertion | Forbidden via Policy; if attempted, audit logs `security.violation` |
| Sequence table empty | Seeder creates initial `next_value = 1` row |

## 3. Confidential ID (spec §6)

### Format

```
{yy}-{GG}-{BB}-{TT}-{RR}

yy = 2-digit registration year
GG = generation number (zero-padded 2 digits)
BB = branch number (zero-padded 2 digits)
TT = team number (zero-padded 2 digits)
RR = performance rank within team (zero-padded 2 digits)
```

Example: `26-03-07-04-02` = registered in 2026, generation 3, branch 7, team 4, rank 2.

### Configurability

Format is **fully configurable** via env:

```
CONFIDENTIAL_ID_FORMAT="{yy}-{GG}-{BB}-{TT}-{RR}"
CONFIDENTIAL_ID_DELIMITER="-"
```

Placeholders:

| Token | Meaning |
|-------|---------|
| `{yy}` | 2-digit year |
| `{yyyy}` | 4-digit year |
| `{GG}` | Generation number, 2-padded |
| `{BB}` | Branch number, 2-padded |
| `{TT}` | Team number, 2-padded |
| `{RR}` | Performance rank, 2-padded |

### Storage

- Stored **encrypted** on `users.confidential_id` (Laravel `encrypt:` cast → TEXT column).
- Decrypted **only** inside services after `UserPolicy::viewConfidential()` passes.
- **Never** included in API Resources or Blade views unless policy check passes (omitted entirely, not nulled).

### Sequence Logic

- Not a single sequence — derived from `applicants.assigned_generation_id`, `assigned_branch_id`, `assigned_team_id` + the user's rank within the team at the moment of generation.
- Rank is fetched from `performance_rankings` (or fallback: `team_members.id` order if no rank yet).
- Format is generated by `ConfidentialIdGenerator::format($applicant)` and **frozen** — the stored value never changes even if the user later moves teams.

### Authorization

```php
// app/Policies/UserPolicy.php
public function viewConfidential(User $viewer, User $target): bool
{
    if ($viewer->hasRole('system_administrator')) return true;
    if ($viewer->hasRole(config('beha.confidential_id_viewers'))) return true;
    return false;
}
```

API Resource:

```php
// app/Http/Resources/UserResource.php
public function toArray($request): array
{
    $data = [
        'id'          => $this->id,
        'official_id' => $this->official_id,
        'name'        => $this->profile->full_name,
        // ... other public fields
    ];

    if ($request->user()?->can('viewConfidential', $this->resource)) {
        $data['confidential_id'] = $this->confidential_id;
    }
    // else: key omitted entirely — never null

    return $data;
}
```

### Protection Checklist

- ❌ Never appear in URLs (`/users/26-03-07-04-02` is forbidden; only `/users/{id}` with internal ID)
- ❌ Never appear in browser HTML for unauthorized users (Blade `@can('viewConfidential', $user)`)
- ❌ Never appear in API responses for unauthorized tokens (Resource policy check)
- ❌ Never appear in logs (custom log formatter redacts `confidential_id` keys)
- ❌ Never appear in exports (Excel / PDF) for unauthorized users (export service checks policy)
- ❌ Never appear in cached responses (cache key includes `user_role_hash`)

## 4. Customer Reference Code (spec §9)

### Format

```
CUS-{YYYY}-{NNNNNN}
```

Examples: `CUS-2026-000001`, `CUS-2026-000002`, ..., `CUS-2027-000001` (resets each year).

### Rules

- One sequence **per year** — `id_sequences.sequence_key = 'cus:2026'`.
- Generated by Record Officer at the final approval step (after duplicate detection passes).
- If duplicate detected and existing customer found, **keep the original reference code** — never re-issue.
- Stored on `customers.reference_code` (UNIQUE).
- Audit trail in `customer_references` (history of issuance).

### Implementation

```php
// app/Services/ID/CustomerReferenceGenerator.php
public function next(int $year): string
{
    return DB::transaction(function () use ($year) {
        $key = "cus:{$year}";
        $seq = $this->sequences->lockNext($key);
        $value = "CUS-{$year}-" . str_pad($seq->next_value, 6, '0', STR_PAD_LEFT);
        $this->sequences->advance($key);
        $this->history->record($key, $value, ...);
        return $value;
    });
}
```

### Integration with Duplicate Detection

```php
// app/Services/Customer/DuplicateDetector.php
public function detect(Customer $candidate): DuplicateResult
{
    $existing = Customer::where('national_id', $candidate->national_id)
        ->orWhere('phone', $candidate->phone)
        ->orWhere('email', $candidate->email)
        ->first();

    if ($existing) {
        return DuplicateResult::existing($existing);
    }
    return DuplicateResult::new($this->refs->next(now()->year));
}
```

## 5. Asset Code (spec §12)

### Format

```
AST-{YYYY}-{NNNNNN}
```

Examples: `AST-2026-000001`.

### Rules

- One sequence per year — `id_sequences.sequence_key = 'ast:2026'`.
- Issued **only** after Executive Officer verifies the property.
- Stored on `properties.asset_code` (UNIQUE, NULL until assigned).
- Mirrored on `property_assets` table for audit (one-to-one with `properties`).
- Once assigned, **immutable** — even if property is unpublished, the code is preserved.

### Implementation

```php
// app/Services/ID/AssetCodeGenerator.php — identical pattern to CustomerReferenceGenerator
public function next(int $year): string { ... 'AST-{year}-{seq}' }
```

## 6. Sequence Service (shared)

```php
// app/Services/ID/IdSequenceService.php
class IdSequenceService
{
    /**
     * Atomically lock + read the next value for a sequence key.
     * Caller is expected to advance() after using the value.
     */
    public function lockNext(string $key): IdSequence
    {
        return DB::transaction(function () use ($key) {
            return IdSequence::lockForUpdate()->where('sequence_key', $key)->firstOrFail();
        });
    }

    public function advance(string $key, int $by = 1): void
    {
        IdSequence::where('sequence_key', $key)->increment('next_value', $by, [
            'last_used_at' => now(),
        ]);
    }

    public function ensureExists(string $key, string $prefix, int $padding): void
    {
        IdSequence::firstOrCreate(
            ['sequence_key' => $key],
            ['prefix' => $prefix, 'padding' => $padding]
        );
    }
}
```

## 7. ID Generation History (audit)

Every ID generation writes a row to `id_generation_history`:

| Column | Example |
|--------|---------|
| `sequence_key` | `official_id` |
| `generated_value` | `BH000123` |
| `subject_type` | `App\Models\User` |
| `subject_id` | `456` |
| `actor_user_id` | `12` (Record Officer) |
| `ip_address` | `192.168.1.42` |
| `user_agent` | `Mozilla/5.0 ...` |
| `payload` | `{"applicant_id": 789, "context": "applicant_onboarding"}` |
| `created_at` | `2026-10-01 12:34:56` |

History is **append-only** (no UPDATE, no DELETE). The table is excluded from soft-delete cleanup — survives forever.

## 8. Workflow Integration

The applicant onboarding workflow calls ID generation at step `record_verification`:

```text
Record Officer reviews applicant
       ↓ (clicks "Generate IDs")
WorkflowService::advance(applicant, action: 'generate_ids')
       ↓
GeneratesIds Action (DB::transaction):
   1. OfficialIdGenerator::next()       → BH000123
   2. ConfidentialIdGenerator::format() → 26-03-07-04-02
   3. Persist to applicants (pending User creation)
   4. Audit log: action='id.generate', category='identity'
       ↓
Record Officer verifies (clicks "Finalize")
       ↓
WorkflowService::advance(applicant, action: 'finalize')
       ↓
Account creation step → System Administrator creates User
       ↓
User.confidential_id is encrypted + stored (immutable)
```

## 9. Edge Cases

| Case | Resolution |
|------|-----------|
| Applicant rejected after ID generation | The ID is "burned" — never reused. Audit log captures reason. The `users` row is never created. |
| User leaves organization | `users.deleted_at` set; Official ID **never** reused. Confidential ID stays in encrypted history. |
| Manual ID change attempt | Forbidden by policy + middleware. Audit log `security.violation`. |
| Sequence table missing row for a year key | Seeder runs at boot to ensure `cus:{year}` and `ast:{year}` exist for the current year. |
| Performance rank unknown (new member) | Default to `01` and re-evaluate later — ID is frozen once stored, so rank remains at issue time. |
| Concurrent ID generation | `SELECT FOR UPDATE` on sequence row serializes; transactions serialize writes. |
